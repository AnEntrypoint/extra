cleetus

Manual build and check

How it works

The static manual is generated by scripts/build-manual.mjs (old name: savi) and proven by scripts/check-manual.mjs (old name: savi). Both take the repository root as their argument, and the npm scripts pass ".". The build writes everything under site/ and the check reads site/ back and compares it with the source tree. The optional checkers scripts/check-ideal-coverage.mjs, scripts/check-ideal-witnesses.mjs, scripts/check-open-items.mjs and scripts/check-featureset.mjs cover the gap registers, and are described on their own pages.

Build (scripts/build-manual.mjs)

  1. Reads the commit (git rev-parse HEAD, or NO_COMMIT), the branch (or DETACHED), and the log as tab-separated history rows (short hash, date, subject).
  2. Walks the root. It skips the directories .git, .playwriter, runs, site, node_modules and sources. It skips the files under .spawn/reference/http/raw/, jayzee-evidence/data/ and jayzee-evidence/maps/witness/. Every other file is a source.
  3. For each source it records bytes, lines, sha256, whether it is text (no NUL byte), a page name, and the body. Text bodies are the file text. Binary bodies are a 16-byte-per-row hex dump with an ASCII column.
  4. Removes site/, then recreates site/raw/ and site/files/ and writes site/.nojekyll (an empty file, so GitHub Pages does not run Jekyll).
  5. Writes site/style.css: a monochrome, monospace stylesheet with a dark colour scheme under prefers-color-scheme dark. Borders are solid, with no rounded corners and no images.
  6. Copies each source byte-for-byte to site/raw/, with the directory named .github rewritten to _github so it is served.
  7. Writes one display page per source at site/files/<hex of the path>.html. The page shows the path, the byte and line counts, TEXT or BINARY, HEX, links to INDEX and RAW, and the file body inside a pre element, HTML-escaped. Image files that are binary get an img element that points to the raw copy.
  8. Writes site/index.html, which groups the files by their top-level directory (or (root)) with a count and byte size for each, followed by the history table. Writes site/404.html.
  9. Writes site/manifest.json with site name Cleetus Manual, commit, branch, sourceCount, textCount, binaryCount, sourceBytes, the per-file records (path, bytes, lines, sha256, text, page) and the history.
  10. Prints one JSON line with commit, branch, files, bytes, text and binary counts.

The page footer reads "REBUILT ON EVERY PUSH TO MAIN" and shows the first seven characters of the commit.

Check (scripts/check-manual.mjs)

The check collects failures and prints one JSON line with ok, sources, text, binary, pages, linksChecked, commit, failures (the first 20) and failureCount. It exits non-zero when any failure exists. For every manifest file it requires:

  • the source exists in the tree;
  • the raw copy exists under site/raw/, with the same sha256 as the manifest;
  • the display page exists, and for text files the text inside its pre element decodes (&lt; &gt; &quot; &#39; &amp;) to exactly the source text;
  • the index page links to the display page;
  • no excluded path is published. The excluded prefixes in the check are .spawn/reference/http/raw/, sources/, and the name WITHHELD.json.

It then walks every .html file under site/ and resolves each href and src that is relative (absolute paths, http, https, mailto, data and protocol-relative links are skipped). It counts linksChecked and reports each target that does not exist.

It requires site/.nojekyll. It requires .github/workflows/publish.yml to contain these seven markers: push:, workflow_dispatch:, node scripts/build-manual.mjs ., node scripts/check-manual.mjs ., configure-pages@v5, upload-pages-artifact@v3, deploy-pages@v5. It requires the manifest's text count plus binary count to equal the file count. When git reports a HEAD, it requires the manifest commit to equal HEAD. It requires ENDPOINTS.md to equal the output of buildEndpointsPage, so a stale endpoint page fails the check.

Workflow (.github/workflows/publish.yml)

The workflow is named publish-manual and runs on every push and on workflow_dispatch. It uses read contents, write pages and id-token write permissions, and a pages concurrency group that does not cancel in-progress runs. The build job checks out with fetch-depth 0, sets up Node version 20, runs the build and the check, then runs configure-pages with enablement true and uploads site/ as a Pages artifact with hidden files included. The deploy job runs only when the ref is refs/heads/main, needs build, and runs deploy-pages.

Other checks

  • check-ideal-coverage.mjs reads docs/JAYZEE-GAPS.md, takes every table row whose first cell is a number, and requires each number to appear as "row N" in ../jayzee/docs/IDEAL.md. It prints the count, the missing IDs, and PASS or FAIL.
  • check-ideal-witnesses.mjs reads ../jayzee/docs/IDEAL.md above its section 5 totals, takes each table row whose cells include partial, and requires each row to name at least one scripts/*.mjs witness that exists under the jayzee root. It prints the count of rows and each error.
  • check-open-items.mjs reads docs/OPEN-ITEMS.md. It requires each "### OPEN-NNN" heading to be unique and sequential from OPEN-001, a Status line with an allowed value (OPEN, RESOLVED, INFERRED, UNVERIFIED, BEHAVIOUR, DIFFERENT-DATASET, HELD-OWNER), a Witness line and a Source paths line. It requires every /workspace/ path cited in the register to exist. It requires every commit id in a Resolution line to exist in the git history of the repository, and it runs a negative witness that a made-up commit is refused. It checks /workspace/gm/closes/ pointers the same way.
  • check-featureset.mjs is the largest checker (about 120 KB). It checks docs/FEATURESET.md against the tree. See featureset-part-1.md for its scope.
  • verify-publish.mjs runs git rev-parse HEAD and gh run list for the publish-manual workflow on main, and passes only when the run for HEAD is completed with conclusion success.

Commands

  • npm run build
  • npm run endpoints
  • npm run check (check-manual, then check-ideal-coverage)
  • npm run check:ideal-coverage
  • npm run check:ideal-witnesses
  • npm run check:featureset
  • npm run verify (needs the gh CLI and network access)

check-open-items.mjs has no npm script in package.json, so it is run directly with node.

Decisions

  • The manual is static and dependency-free. The sources say "No npm packages are required", and the scripts import only Node built-ins.
  • The manual shows exact bytes. Each file is copied to raw/ and its text is compared with the display page. This is the completeness proof: the check fails if a display page differs from the source by a single character.
  • Raw copies and display pages use an encoded path. Display pages are named by the hex of the path, so no path separator or case issue reaches the file system.
  • The .github directory is served as _github in raw/ (build-manual.mjs rewrites that segment). The sources do not state the reason. .nojekyll is also written, which the check requires.
  • Some paths are withheld by exclusion: runs/, sources/, .playwriter/, the raw HTTP captures and the jayzee-evidence data and witness maps. The README says only that some files are not published. The withholding is by path, not by content scanning, and the lists are in scripts/build-manual.mjs and scripts/check-manual.mjs.
  • The check deliberately verifies that the site commit equals HEAD, so a stale site cannot be published silently.
  • The site is rebuilt on each push, not on a schedule. The publish workflow is the only deployment.
  • The ideal-coverage and ideal-witness checks read a document outside this repository (../jayzee/docs/IDEAL.md). They fail when it is missing, which is recorded as an explicit FAIL, not a skip.

Open gaps

  • The check does not compare the site with a fresh build for every file. It checks the manifest sha256 against the raw copy and the display page text against the source, which together prove the committed content, but it does not rebuild and diff.
  • The withheld lists in build-manual.mjs and check-manual.mjs differ: the build also excludes jayzee-evidence/data/ and jayzee-evidence/maps/witness/, while the check does not list them. The check verifies only that they are absent from the site, so an extra exclusion in the build would not be caught by the check.
  • check-open-items.mjs is not wired into package.json or the workflow, so it runs only by hand.
  • verify-publish.mjs needs the gh CLI and a network connection; nothing in the sources records a run of it.
  • The two ideal checks depend on /workspace/jayzee/docs/IDEAL.md, which exists at the time of writing (167.2 KB) but is outside this repository, so a clone without the jayzee checkout will fail them.
