How it works

This page reproduces /workspace/spawn/maps/spawn-root-worlds-map.md (old name: spawn) in full. The source is a read-only map of the 74 worlds linked from the root page of the jayzee site (www.spawn.co), taken from browser reads on 2026-11-07 between about 10:50 and 11:05 UTC. The run ids are 2026-11-07-10-49-42-a2cf05 (actionSeq 28, 33, 38, 43), and the run log is at /workspace/spawn/runs/2026-11-07-10-49-42-a2cf05/log.jsonl (old name: spawn).

The map has these parts, in the source's order:

  1. A field list and a 74-row table. Fields are URL path, HTTP status, title, genre (from JSON-LD), datePublished, dateModified, the reviews line from body text, and the newest update from body text. Descriptions (meta) were captured only for the first 20 worlds, so worlds 21 to 74 have no description field. Counts drift between reads; the source gives the example @lanmower/deepfall showing 4 plays earlier and 6 plays in the map.
  2. A list of what is not mapped: the 38 creator profile pages (only the worlds were read), descriptions and version counts for worlds 21 to 74, and spawnfile.io asset URLs for other creators' worlds.
  3. A world-store GLB scan on three worlds (superseded for GLB purposes, see below).
  4. Creator profiles of 37 root-linked handles.
  5. Public API routes from openapi.json and llms.txt.
  6. World-store contents and value types.
  7. Spatial storage and world-store to local-store ties, read from minified chunks (inferred, not confirmed by a live run).
  8. GLB URLs: where they are, and the working CLI route (confirmed for one world).
  9. The full CDN scan result for 2848 feed worlds (16 shards).
  10. The spawnfile-family scan and the missing-head reconciliation.

Titles are reproduced verbatim, including titles that contain the word Spawn, because they are world names as published on the site and not references to the project. Hostnames and URLs are reproduced verbatim.

How the root world list is used

The 74 root worlds are the set the map was built from. The feed enumeration (below) covers 2848 worlds, so the root map is a subset of the feed set. Entry 69 (GTA Manhattan, /@starmist/gta-manhattan) is the world whose GLB chain (file map, then CDN HEAD and magic) was witnessed end to end. Entry 6 (GTA Earth, /@borickk/gta-earth) and entry 26 (Need for Spawn, /@chucky/need-for-spawn) were scanned for values in the earlier world-store pass, and entry 38 (The Savi Gallery) was scanned in an earlier session scan listed under its world uuid.

World-store GLB scan (superseded for GLB purposes)

Method: /tmp/spawn-probe/worldscan.sh (old name: spawn) <uuid>. It fetches play.spawn.co/world-store/git/<uuid-no-dashes>/head.json, then world-store/manifests/<manifest> (regex {"v":1,"hashes":[...]} after a binary prefix), then world-store/values/<hash> for each hash. A value counts as direct GLB when its body starts with glTF. World UUIDs come from the world page HTML, field play.spawn.co/session/world%3A<uuid>%40live.

Cell paths and place config (chunk-a.js)

  • Cell scene key: Gt=((e,t=CvB)=>"places/"+(e+("/cells/"+(t+".scene")))). So a cell's scene file is places/<place>/cells/<cell>.scene. The default cell name CvB is not decoded.
  • Place existence check: "places/"+t+"/config.yaml" must be a key in the world's file map (a string value). So a place is a directory with config.yaml, and its cells live under cells/.
  • Cell-page merge (Yzv): for each level, for each cellPages entry, the page's JSON is read from the value map, l.cells is merged into i.cells, and l.imports is read. A cell's slice field is copied into the key Gt(place, cell). This matches the pt check above.
  • Cell-to-place parse (cA) is used to recover the place from a cell key. Its body is not in the saved chunks and was not decoded.
