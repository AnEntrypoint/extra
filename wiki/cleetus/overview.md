# Overview of cleetus

## How it works

cleetus is the project that was checked out at /workspace/savi (old name: savi). It is a documentation and verification repository. It holds no game or server code of its own. It documents the featureset of the upstream platform, records the open gaps between that featureset and the jayzee port (old name: spawn), and builds a static, byte-exact manual of its own files.

The repository is a git checkout on branch main with origin AnEntrypoint/savi. The head at the time of writing is 5a30f94. The published manual is at https://anentrypoint.github.io/savi/ (the URL is kept verbatim).

Every push runs .github/workflows/publish.yml (workflow name publish-manual), which builds and checks the site. The deploy job runs only for refs/heads/main, so a push to main rebuilds the site, checks it, and deploys it to GitHub Pages. The build uses no npm packages. The generated site is written to site/.

### Repository layout

Top-level files:

- README.md: the title "Savi Manual", the build and check commands, and the published URL. It explains that the manual shows every committed file as exact text, or as a hex dump when binary, with a raw copy and a commit history. It also says that some files are not published.
- ENDPOINTS.md: the generated endpoint status page. It lists 93 named endpoints in four groups. It is generated by scripts/endpoints.mjs and must not be edited by hand. See [endpoints.md](endpoints.md).
- manual-worklist.json: a JSON list of seven research units (corpus, structure, automation, design, security, validation) with the angle and query for each. It was generated for 2026-11-06 for the workspace /workspace/savi (old name: savi). See [manual-worklist.md](manual-worklist.md).
- package.json: the package named cleetus-direct-manual, private, with type module and seven npm scripts. See the build section below.
- .gitignore: ignores node_modules/, site/, .playwriter/, runs/, .spawn/engine/.git/, .spawn/reference/http/raw/, .DS_Store and sources/.

Top-level directories, as they exist on disk:

- .claude/, .github/ (contains workflows/publish.yml), .playwriter/ (ignored, browser-tool state), .spawn/ (the reference snapshot of the upstream platform, read-only), docs/ (the register and briefs), gaps/ (two survey documents), runs/ (ignored run output), scripts/ (build, check and endpoint tooling plus openapi.json), site/ (ignored generated manual), sources/ (ignored), jayzee-engine/ (engine analysis notes), jayzee-evidence/ (evidence directory whose data and witness maps are withheld from publication).

Files under docs/: FEATURESET.md, JAYZEE-GAPS.md, NETCODE-BRIEF-FOR-JAYZEE.md, OPEN-ITEMS.md, PARITY-BRIEF-FOR-JAYZEE.md and PARITY-INPUTS.md. See [docs-folder.md](docs-folder.md).

Files under gaps/: morluto-rea-pr-9234-ci-findings.md and netcode-optimization-gaps.md. See [morluto-ci-findings.md](morluto-ci-findings.md) and [netcode.md](netcode.md).

Files under scripts/: build-manual.mjs, check-manual.mjs, verify-publish.mjs, endpoints.mjs, check-ideal-coverage.mjs, check-ideal-witnesses.mjs, check-open-items.mjs, check-featureset.mjs, and openapi.json. See [manual-build.md](manual-build.md) and [endpoints.md](endpoints.md).

### How to build it

Run these commands from the repository root. No npm packages are required.

- npm run build: runs node scripts/build-manual.mjs . and writes site/.
- npm run endpoints: runs node scripts/endpoints.mjs . and rewrites ENDPOINTS.md.
- npm run check: runs node scripts/check-manual.mjs . and then node scripts/check-ideal-coverage.mjs.
- npm run check:ideal-coverage, npm run check:ideal-witnesses, npm run check:featureset: each runs one checker.
- npm run verify: runs node scripts/verify-publish.mjs . and asks GitHub for the publish run of HEAD (it needs the gh CLI).

The order that the README gives is build, endpoints, check. Build rebuilds site/ from the committed tree, and check proves the result.

## Decisions

- The manual shows every file as exact text, and binary files as hex dumps, with no summary replacing source text. The reason is in the README and in the build script, which writes the raw bytes next to the display page.
- No npm dependencies. scripts/build-manual.mjs and scripts/check-manual.mjs use only node built-ins (node:crypto, node:child_process, node:fs, node:path), so the build needs only Node.
- The site is rebuilt and deployed on every push to main, so the published manual cannot drift from the commit. scripts/verify-publish.mjs checks that the latest publish run for HEAD completed with success.
- Some files are withheld from publication: .spawn/reference/http/raw/, sources/, runs/, .playwriter/, site/, and in the build also jayzee-evidence/data/ and jayzee-evidence/maps/witness/. The reason given in the sources is that they hold raw captures and run state, not reviewed source. The withholding list is the one in scripts/build-manual.mjs.
- .spawn/engine and the jayzee references under .spawn/reference/ are read-only analysis snapshots. They are not maintained or refreshed by cleetus (OPEN-ITEMS, register header).
- The owner rule that comments are not kept as prose is applied to the code: the netcode brief tells jayzee to put wire layouts in a doc, not in comments (docs/NETCODE-BRIEF-FOR-JAYZEE.md, J2).

## Open gaps

- The site/manifest.json commit can lag HEAD until the build is rerun. OPEN-018 in docs/OPEN-ITEMS.md records a case (site at 501c76e, HEAD 6c39a16) and its resolution at c398faf. The resolution is recorded, and the status stays OPEN.
- verify-publish.mjs depends on the gh CLI and network access. Nothing in the sources records a run of it.
- .spawn/reference/engine-deep/README.md once said that cleetus was not a git repository. OPEN-018 records the correction at c398faf.
